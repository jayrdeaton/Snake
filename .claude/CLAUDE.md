# Snake

A classic Snake game with Solo, Vs CPU, and local simultaneous split-screen 2 Player modes (Expo/React Native, Skia-rendered). Part of the `@rific`/`@tastic`/InfiniteToken app ecosystem - depends on `@rific/auto-paper`, `@rific/feedback-press`, `@rific/focus-chain`, `@rific/scroll-view`, `@rific/splash-gate`, `@rific/toaster`, `@rific/updater`, `@tastic/achievements`, `@tastic/core`, `@tastic/hud`, `@tastic/input`, `@tastic/profile`, `@tastic/split-screen`. (`@rific/drawer` was a dependency until 2026-09-17 - removed along with the dead `HistoryDrawerContainer` code that was its only call site, see below.) (`@rific/resizable-input` was also a dependency until 2026-10-14 - never imported anywhere and not a peer of any installed package, so it was uninstalled.) The most complex app in the fleet to migrate so far after Utility - real Redux Toolkit state (`@reduxjs/toolkit`, `react-redux`, `redux-persist`), plus dependencies no other game in the fleet has yet (`react-native-keyboard-controller`, `expo-linking`, `expo-secure-store`, `@shopify/flash-list`).

**Expo has changed.** Read the exact versioned docs at https://docs.expo.dev/versions/v57.0.0/ before writing any code - don't rely on general Expo knowledge, this app is on SDK 57 specifically.

## Commands

```bash
npm run lint          # expo lint .
npm run fix            # expo lint . --fix
npm test               # Jest (24 suites, 265 tests)
npm run test:watch     # Jest --watchAll
npm run typecheck      # tsc
npm run verify         # lint + test + typecheck
npm run doctor         # expo install --fix && expo-doctor
npm start              # Expo dev server
npm run client          # Expo dev server (dev client build)
```

Always run `npm run lint` before finishing any task. This is an app (`"private": true`, no publish scripts) - `verify` doesn't include a build step.

There are no per-profile `build:development`/`build:preview`/`build:production` or `update:development`/`update:preview`/`update:production` scripts in this app's `package.json` at all, and no `npm run verify && ` prefix anywhere in it - just one bare `"build": "rific-updater-build"` and `"update": "rific-updater-update"`, delegating straight to `@rific/updater`'s own CLI bins, which run this app's `npm run verify` as their first step internally, before any build/update logic proceeds. See [`@rific/updater`'s own README](../Expo-Updater/README.md) ("Build & update scripts" / "Verify-gating lives in the CLI, not in `package.json`") for the full mechanism - the per-script `npm run verify && ` prefix this paragraph used to describe (and which every sibling app's CLAUDE.md still describes the same way) predates these bins and no longer applies once an app is on them.

## Audit fixes (2026-10-08)

Seven fixes from the verified 2026-09-29 fleet audit (`verified-2026-10-08.json`), the shared parts written to be identical across AirHockey, BoxHockey, LightCycles, Pong and Snake. Nothing here has been run on a device or in a browser yet.

- **Background pause (F085):** `game.tsx` calls `@tastic/core`'s `useBackgroundPause(() => phase !== 'gameOver' && !settingsOpen && !confirmVisible)`. Any AppState other than `active` mid-match (home, app switch, a phone call, iOS Control Center or Notification Center; a hidden tab on web, which react-native-web reports as `background`) latches `backgroundPaused`, unless the match is over or a dialog already holds the pause. `paused = settingsOpen || confirmVisible || backgroundPaused` feeds `useSnakeState`'s new trailing `paused` parameter (the rAF tick loop, CPU included, stops; after a resume the first tick waits a full interval), both input layers' `enabled`, `liveplay.activelyPlaying` (Edge Guard), and the countdown: `OnboardingOverlay` is unmounted while paused, so its timers stop and the count restarts from 3. The latch does not clear on return. A centered `ConfirmDialog` titled `Paused` (icon `pause-circle-outline`, the same `progressMessage` and `overlayRotation` as Quit Match?) offers an outlined `Quit` (`safeBack` at once, no second confirmation) and a contained `Resume` (clears the latch). So that `paused` exists before `useSnakeState`, `settingsOpen`, `useQuitConfirmation` and `localPhase`'s `useState` now sit above that hook. `localPhase` in particular has to be declared before `useBackgroundPause`'s getter reads `phase`: declared after it, the React Compiler skips memoizing the whole screen (`react-hooks/preserve-manual-memoization` warns on `handleBeginPlaying`/`handleRetry`).
- **Countdown under Settings (F084):** fixed by the same `!paused` gate. Opening Settings or Quit Match? during the 3-2-1 used to let the countdown finish behind the dialog, so the round (and the CPU) started underneath it.
- **Scales (F062):** `tickSnake` never read `effects.shield`, so Scales did nothing. It now follows LightCycles' Shield rule. A shield is active while `tick <= expiresAtTick` and is used up by its first hit; walls and out-of-bounds always kill. In a head-on where exactly one snake is shielded, that snake moves into the cell and the other dies; both or neither shielded stays a draw. A shielded body or obstacle hit survives and moves into the cell. If the cell is part of a live snake's body (its own included), that body loses the hit cell and everything behind it (non-exported `trimSnakeBodyAtCell` and `locateBrokenBody`, applied after the sub-step's commits on both the death and normal paths; a snake that died that sub-step keeps its body for the death fade). Since a body can now shrink inside a tick, score and the food respawn come from a per-tick `foodEaten` count, not the change in length. `snakeAi` is not shield-aware, the same as LightCycles' `cpuAi`. On screen, a cut shows up one tick late: `SnakeBoardCanvas`'s glide treats a same-tick trim as an ordinary slide, as it already did for Constrict.
- **Tap-to-activate (F063):** `TouchInputLayer`'s Tap is now LightCycles' (`maxDistance(TAP_MAX_DISTANCE)`, `hitSlop({})`, activates only when RNGH reports `success`), so a quick swipe released inside the Tap's time limit no longer spends a held powerup. `game.tsx`'s `handleActivate` now plays a `selection()` haptic next to `playActivate()` when a powerup is held. Needs an on-device check with powerups on: quick swipes must not activate, and a still tap must, in Solo and in both 2 Player zones.
- **Per-seat stats (F021):** `statsEngine.ts`'s `RoundOutcome` is now `{ mode, seats, winner }`: `seats` holds a `SeatRoundOutcome` (`{ score, snakeLength }`, `snakeLength` being `peakLength`) for each human seat only, so the CPU never counts. `RoundContext.profileIds` is seat-keyed, and each profile is bumped from its own seat's numbers and result (`seatResult`, via `@tastic/achievements`' `resultFor`), so a 2 Player loser's profile records its own loss and score instead of seat 1's win and the higher score. The device bucket counts the best score and longest snake of either human, with seat 1's result. `useGameStats.tsx`'s `RecordRoundOutcomeContext` and its flattening are gone. In `game.tsx`, `recordedScore`/`viewerStats`/`isNewHighScore` became `seatStats(seat)`, `winner` and `newHighScoreSeats`.
- **2 Player result cards (F170):** `GameOverDialog` has a new optional `seatResults` prop (`Record<SnakeId, GameOverSeatResult>`; the exported `GameOverSeatResult` is `{ outcome, score, opponentScore, highScore, isNewHighScore, color }`). `game.tsx` passes it in 2 Player only, built per seat by `gameOverSeatResult(seat)`, and the dialog then shows one compact card per seat in `OnboardingOverlay`'s zones and rotations: that seat's own YOU WIN!/YOU LOSE!/DRAW, its YOU/OPPONENT scores, its BEST or New High Score, a one-line unlock summary in the seat's color (`<title> unlocked!` or `N achievements unlocked!`, like LightCycles' `RoundOverDialog` badge), and Quit/Retry. Not a row per unlock: device-wide unlocks are broadcast onto both cards, so a first round with profiles can list five or more, and a card taller than half a short phone gets clipped by its zone's `overflow: 'hidden'`, Quit/Retry included. Either seat's button acts at once (no LightCycles-style Rematch handshake). Solo and Vs CPU keep the single card. Guest seats (no profile) share the device-wide bucket, so in 2 Player a guest seat only gets New High Score when its score is also the round's top human score (two guests past the old best used to both claim it), and a guest's BEST is that shared device best, which can be the other guest's score (Jay can still choose to hide BEST for guests). Needs a check on a short phone (iPhone SE) in both holds.
- **Ghost profiles (F145):** `useProfiles.tsx` dispatches `@tastic/profile`'s `profileSelectionActions.pruneToRoster(ids)` after both `profilesActions.setAll` calls (the initial reconcile and `onRemoteChange`), so a seat that points at a profile a sibling app deleted falls back to guest instead of recording stats and unlocks for a ghost id. The two edits are byte-identical across the 5 games. Stats already written under a ghost id are left alone on purpose: the shared store reads as `[]` on any error, so pruning stats on a remote change could wipe every player.
- **Control schemes (F109):** this app's `assignControlScheme` became `@tastic/input`'s `assignSeatScheme` (see "Control-scheme collisions" above), and `src/utils/keyboardControls.ts` and its test lost it.

Until then this app runs on packed tarballs installed with `npm install --no-save`, so a fresh `npm install` fails to typecheck.

## OS portrait lock (2026-10-08)

The OS is locked to portrait on every device and the app draws all rotation itself (`@tastic/core`'s `OrientationProvider` reads the accelerometer). `@tastic/core`'s Expo config plugin (`"@tastic/core"` in `app.json`'s `plugins`) owns every native setting that depends on: `orientation: "portrait"`; `ios.requireFullScreen` plus a Portrait-only iPad orientation list (audit F009: without it Expo forces all four iPad orientations, so iOS turned the screen on top of the app's own rotation, and Split View, Slide Over and Stage Manager are the price); and `android:appCategory="game"` (Android 16 and later ignore the portrait lock on tablets and unfolded foldables, except for games). Don't set any of those by hand here, and don't add `expo-screen-orientation` (it re-enables upside down on home-button iPhones). The why behind each is in @tastic/core's README. Check the result with `npx expo config --type introspect`; it only takes effect in a new native build.

## Xcode 26 image pin (remove on Expo SDK 58)

`eas.json` pins the `preview` and `production` iOS builds to `macos-tahoe-26.5-xcode-26.6` (set fleet-wide 2026-10-14). An app linked against the iOS 27 SDK aborts at launch on iOS 27 ("UIScene life cycle is required for apps built with this SDK") unless it adopts the UIScene life cycle, which SDK 57's native template doesn't do and SDK 58's does. A build made with Xcode 26 runs fine on iOS 27. **When this app moves to Expo SDK 58, remove both `ios.image` pins and this section**, so builds go back to EAS's default image for the SDK. Local builds (`expo run:ios`, the `development` profile) ignore the pin and use this Mac's Xcode 27, so until then they crash at launch on an iOS 27 device or simulator.
