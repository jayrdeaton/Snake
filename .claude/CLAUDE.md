# Snake

A classic Snake game with Solo, Vs CPU, and local simultaneous split-screen 2 Player modes (Expo/React Native, Skia-rendered). Part of the `@rific`/`@tastic`/InfiniteToken app ecosystem - depends on `@rific/auto-paper`, `@rific/feedback-press`, `@rific/focus-chain`, `@rific/gestures`, `@rific/scroll-view`, `@rific/splash-gate`, `@rific/toaster`, `@rific/updater`, `@tastic/achievements`, `@tastic/core`, `@tastic/hud`, `@tastic/input`, `@tastic/profile`, `@tastic/split-screen`. (`@rific/drawer` was a dependency until 2026-09-17 - removed along with the dead `HistoryDrawerContainer` code that was its only call site, see below.) (`@rific/resizable-input` was also a dependency until 2026-10-14 - never imported anywhere and not a peer of any installed package, so it was uninstalled.) The most complex app in the fleet to migrate so far after Utility - real Redux Toolkit state (`@reduxjs/toolkit`, `react-redux`, `redux-persist`), plus dependencies no other game in the fleet has yet (`react-native-keyboard-controller`, `expo-linking`, `expo-secure-store`, `@shopify/flash-list`).

**Expo has changed.** Read the exact versioned docs at https://docs.expo.dev/versions/v57.0.0/ before writing any code - don't rely on general Expo knowledge, this app is on SDK 57 specifically.

## Commands

```bash
npm run lint          # expo lint .
npm run fix            # expo lint . --fix
npm test               # Jest (29 suites, 300 tests)
npm run test:watch     # Jest --watchAll
npm run typecheck      # tsc
npm run verify         # lint + test + typecheck
npm run doctor         # expo install --fix && expo-doctor
npm start              # Expo dev server
npm run client          # Expo dev server (dev client build)
npm run build:web       # verify, then the web export for games.infinitetoken.com/snake/
```

Always run `npm run lint` before finishing any task. This is an app (`"private": true`, no publish scripts) - `verify` doesn't include a build step.

**Builds and OTA updates:** the `build` and `update` scripts are plain `eas build` and `eas update`, with profiles in `eas.json` (`development`, `preview`, `production`). Pass the profile through, e.g. `npm run build -- --profile preview` or `npm run update -- --branch production --environment production --message "..."`. Nothing in them runs `verify`, so run `npm run verify` first. An OTA update also bumps `otaVersion` in `src/constants/release.ts` (the version label players see), committed before publishing. They used to be `@rific/updater`'s `rific-updater-build`/`rific-updater-update` bins, which @rific/updater 0.7.0 removed; the package stays for its OTA update hook. `build:web` is the one exception: it chains `npm run verify &&` before the web export (see "Web on games.infinitetoken.com" below).

## Fleet-wide drift audit round 3 (2026-09-18)

A third fleet-wide scan found three real gaps here, all fixed:

- **Background pause (F085):** `game.tsx` calls `@tastic/core`'s `useBackgroundPause(() => phase !== 'gameOver' && !settingsOpen && !confirmVisible)`. Any AppState other than `active` mid-match (home, app switch, a phone call, iOS Control Center or Notification Center; a hidden tab on web, which react-native-web reports as `background`) latches `backgroundPaused`, unless the match is over or a dialog already holds the pause. `paused = settingsOpen || confirmVisible || backgroundPaused` feeds `useSnakeState`'s new trailing `paused` parameter (the rAF tick loop, CPU included, stops; after a resume the first tick waits a full interval), both input layers' `enabled`, `liveplay.activelyPlaying` (Edge Guard), and the countdown: `OnboardingOverlay` is unmounted while paused, so its timers stop and the count restarts from 3. The latch does not clear on return. A centered `ConfirmDialog` titled `Paused` (icon `pause-circle-outline`, the same `progressMessage` and `overlayRotation` as Quit Match?) offers an outlined `Quit` (`safeBack` at once, no second confirmation) and a contained `Resume` (clears the latch). So that `paused` exists before `useSnakeState`, `settingsOpen`, `useQuitConfirmation` and `localPhase`'s `useState` now sit above that hook. `localPhase` in particular has to be declared before `useBackgroundPause`'s getter reads `phase`: declared after it, the React Compiler skips memoizing the whole screen (`react-hooks/preserve-manual-memoization` warns on `handleBeginPlaying`/`handleRetry`).
- **Countdown under Settings (F084):** fixed by the same `!paused` gate. Opening Settings or Quit Match? during the 3-2-1 used to let the countdown finish behind the dialog, so the round (and the CPU) started underneath it.
- **Scales (F062):** `tickSnake` never read `effects.shield`, so Scales did nothing. It now follows LightCycles' Shield rule. A shield is active while `tick <= expiresAtTick` and is used up by its first hit; walls and out-of-bounds always kill. In a head-on where exactly one snake is shielded, that snake moves into the cell and the other dies; both or neither shielded stays a draw. A shielded body or obstacle hit survives and moves into the cell. If the cell is part of a live snake's body (its own included), that body loses the hit cell and everything behind it (non-exported `trimSnakeBodyAtCell` and `locateBrokenBody`, applied after the sub-step's commits on both the death and normal paths; a snake that died that sub-step keeps its body for the death fade). Since a body can now shrink inside a tick, score and the food respawn come from a per-tick `foodEaten` count, not the change in length. `snakeAi` is not shield-aware, the same as LightCycles' `cpuAi`. On screen, a cut shows up one tick late: `SnakeBoardCanvas`'s glide treats a same-tick trim as an ordinary slide, as it already did for Constrict.
- **Tap-to-activate (F063):** `TouchInputLayer`'s Tap is now LightCycles' (`maxDistance(TAP_MAX_DISTANCE)`, `hitSlop({})`, activates only when RNGH reports `success`), so a quick swipe released inside the Tap's time limit no longer spends a held powerup. `game.tsx`'s `handleActivate` now plays a `selection()` haptic next to `playActivate()` when a powerup is held. Needs an on-device check with powerups on: quick swipes must not activate, and a still tap must, in Solo and in both 2 Player zones.
- **Per-seat stats (F021):** `statsEngine.ts`'s `RoundOutcome` is now `{ mode, seats, winner }`: `seats` holds a `SeatRoundOutcome` (`{ score, snakeLength }`, `snakeLength` being `peakLength`) for each human seat only, so the CPU never counts. `RoundContext.profileIds` is seat-keyed, and each profile is bumped from its own seat's numbers and result (`seatResult`, via `@tastic/achievements`' `resultFor`), so a 2 Player loser's profile records its own loss and score instead of seat 1's win and the higher score. The device bucket counts the best score and longest snake of either human, with seat 1's result. `useGameStats.tsx`'s `RecordRoundOutcomeContext` and its flattening are gone. In `game.tsx`, `recordedScore`/`viewerStats`/`isNewHighScore` became `seatStats(seat)`, `winner` and `newHighScoreSeats`.
- **2 Player result cards (F170):** `GameOverDialog` has a new optional `seatResults` prop (`Record<SnakeId, GameOverSeatResult>`; the exported `GameOverSeatResult` is `{ outcome, score, opponentScore, highScore, isNewHighScore, color }`). `game.tsx` passes it in 2 Player only, built per seat by `gameOverSeatResult(seat)`, and the dialog then shows one compact card per seat in `OnboardingOverlay`'s zones and rotations: that seat's own YOU WIN!/YOU LOSE!/DRAW, its YOU/OPPONENT scores, its BEST or New High Score, a one-line unlock summary in the seat's color (`<title> unlocked!` or `N achievements unlocked!`, like LightCycles' `RoundOverDialog` badge; gone since 2026-10-20, see "Unlock toasts" at the end), and Quit/Retry. Not a row per unlock: device-wide unlocks are broadcast onto both cards, so a first round with profiles can list five or more, and a card taller than half a short phone gets clipped by its zone's `overflow: 'hidden'`, Quit/Retry included. Either seat's button acts at once (no LightCycles-style Rematch handshake). Solo and Vs CPU keep the single card. Guest seats (no profile) share the device-wide bucket, so in 2 Player a guest seat only gets New High Score when its score is also the round's top human score (two guests past the old best used to both claim it), and a guest's BEST is that shared device best, which can be the other guest's score (Jay can still choose to hide BEST for guests). Needs a check on a short phone (iPhone SE) in both holds.
- **Ghost profiles (F145):** `useProfiles.tsx` dispatches `@tastic/profile`'s `profileSelectionActions.pruneToRoster(ids)` after both `profilesActions.setAll` calls (the initial reconcile and `onRemoteChange`), so a seat that points at a profile a sibling app deleted falls back to guest instead of recording stats and unlocks for a ghost id. The two edits are byte-identical across the 5 games. Stats already written under a ghost id are left alone on purpose: the shared store reads as `[]` on any error, so pruning stats on a remote change could wipe every player.
- **Control schemes (F109):** this app's `assignControlScheme` became `@tastic/input`'s `assignSeatScheme` (see "Control-scheme collisions" above), and `src/utils/keyboardControls.ts` and its test lost it.

The Paused dialog itself and the countdown gate (`OnboardingOverlay` unmounted while paused) live in `game.tsx`, which has no render test; `useBackgroundPause` itself is tested in `@tastic/core`.
- **Known gaps, not fixed here:** (1) `pruneToRoster` runs on whatever `onRemoteChange` gets, and `@tastic/profile`'s shared read returns `[]` on any read or parse error, so one failed App Group read on a foreground resume clears both seats' selections for good (the profiles come back on the next good read, the selections don't). The fix belongs in `@tastic/profile` (tell a failed read from an empty roster and skip `onRemoteChange` on error), then the five apps' tests. (2) `selectProfile` has no swap-on-conflict: `takenProfileId` is only a picker hint and is unset in 1 Player, so a 1 Player pick of seat 2's saved profile leaves both seats on one id, and the next 2 Player round bumps that profile twice (played +2, a win and a loss). ## OS portrait lock (2026-10-08)

The OS is locked to portrait on every device and the app draws all rotation itself (`@tastic/core`'s `OrientationProvider` reads the accelerometer). `@tastic/core`'s Expo config plugin (`"@tastic/core"` in `app.json`'s `plugins`) owns every native setting that depends on: `orientation: "portrait"`; `ios.requireFullScreen` plus a Portrait-only iPad orientation list (audit F009: without it Expo forces all four iPad orientations, so iOS turned the screen on top of the app's own rotation, and Split View, Slide Over and Stage Manager are the price); and `android:appCategory="game"` (Android 16 and later ignore the portrait lock on tablets and unfolded foldables, except for games). Don't set any of those by hand here, and don't add `expo-screen-orientation` (it re-enables upside down on home-button iPhones). The why behind each is in @tastic/core's README. Check the result with `npx expo config --type introspect`; it only takes effect in a new native build.

## Web on games.infinitetoken.com (2026-10-17)

The web build is served at https://games.infinitetoken.com/<game>/ with every other Tastic game on that one origin, so they share browser storage and, through it, `@tastic/profile`'s player roster (the web side of the App Group). Games-Web, the hub at games.infinitetoken.com, proxies `/<game>/*` to this project's own production deployment (see its CLAUDE.md). Before this, each game had its own subdomain. Same section in Hangman, LightCycles, Snake and Solitaire.

- **The build:** `build:web` runs `verify`, then `WEB_BASE_URL=/<game> expo export -p web --output-dir web-build/<game>`. `app.config.ts` (identical in all four) turns `WEB_BASE_URL` into `experiments.baseUrl` only when it's set: a base URL also reaches native bundles, asset paths and EAS updates, so it never goes in `app.json`. Expo writes the export flat and prefixes the URLs inside it, so the output folder is what puts the files under `/<game>/`, and this project's own deployment serves the same paths the hub forwards. Building more than one game locally: run them one at a time with `--clear`, or Metro's shared cache leaks one app's config into the next.
- **`vercel.json`** (identical in all four): `buildCommand` is `npm run build:web`, the output is `web-build`, `cleanUrls` is on, and a `/<game>/...` path that isn't a file rewrites to `/<game>/index`, the path `cleanUrls` gives `index.html` (the form Vercel's instant static serving answers; see the 2026-10-16 note). A request on the old `<game>.infinitetoken.com` domain (still attached to this project) redirects to the same path under `games.infinitetoken.com/<game>/`, and its `/privacy` to the hub's privacy page. The host pattern names the four games rather than matching any subdomain, so it can never match `games.` itself. The bare root has its own rule, because Vercel's `/:path*` doesn't match `/` (seen live on Solitaire v1.2.0 2026-10-17: `/klondike` redirected, `/` was a 404). The redirects stay temporary until the move is checked live.
- **Privacy and store links:** the per-game `public/privacy.html` is gone. The one privacy policy is the hub's `/privacy`, and `store.config.json` points there, with support at `/support` and marketing at `/<game>`.
- **Storage:** redux-persist's `keyPrefix` is `'<game>:'`, so this game's state is `<game>:root` in localStorage instead of the `persist:root` every game used to write, which on one origin would have been each other's state. REHYDRATE still reports key `root`, so `guideSlice`'s `persistKey` is unchanged. Any other key this game writes must be namespaced by the game too. The prefix applies on native as well; saves under the old key were abandoned (nothing has shipped).
- **Skia** (Snake, LightCycles): `canvaskit.wasm` is fetched from `/<game>/canvaskit.wasm` via hud's `loadSkiaWeb` (`@tastic/hud/skia`, 0.24.0+), which builds the URL from the inlined `EXPO_BASE_URL`, so it no longer depends on the page's path. See "Skia on web" below.

## Skia on web (2026-10-17)

## Keep Awake (2026-10-15, on @rific/core since 2026-10-17)

`/game` keeps the screen from dimming and locking while it's up (`useKeepAwake('game')` from `@rific/core`, next to `useBackgroundPause`, released on unmount), unless the player turns off the Keep Awake row in Settings (default on, read live so the toggle applies mid-match). ## Status bar: per-screen options (2026-10-15)

The OS status bar is set through react-native-screens' screen options, never a `StatusBar` component. `_layout.tsx`'s `RootNavigator` spreads `@tastic/core`'s `useRotationAwareStatusBar()` (0.14.0+) into the root Stack's `screenOptions`, which hides the bar while the content is rotated off portrait (no `locked` argument: `OrientationBridge` freezes the reading it follows), and /game hides it for the whole round through its own `Stack.Screen` options (`GAME_OPTIONS`, `{ statusBarHidden: true }`), set in the layout so they apply as the screen is pushed rather than one effect later. No style is passed: react-native-screens' default (`auto`, following the system appearance) is what expo-status-bar's `auto` gave before.

Why: an app linked against the iOS 27 SDK (Xcode 27) can't set the status bar through `UIApplication` any more (UIKit's `UIApplication.h`: setting it "does nothing if ... linked against SDK versions 27.0 or later"), and that is all React Native's `StatusBar`, and so expo-status-bar, does on iOS. `@tastic/core`'s config plugin now sets `UIViewControllerBasedStatusBarAppearance: true`, which react-native-screens needs, and under which every mounted `StatusBar` logs an `RCTLogError` (a red box in dev). So nothing may mount one: `<RotationAwareStatusBar />` (removed from core) and /game's `<StatusBar hidden />` are gone, `Theme.tsx` passes auto-paper's Provider `statusBar={false}` (0.13.2+, which also covers `Appbar.Header`), and expo-status-bar is no longer a dependency or an app.json plugin (its plugin did nothing without options). Pinned by `src/__tests__/statusBar.test.tsx` (no source file imports expo-status-bar or React Native's `StatusBar`; Theme turns auto-paper's off) and `src/__tests__/app/_layout.test.tsx` (the root Stack's options, and /game's).

- **The hide only shows in a Release build.** In a dev-client (development) build, expo-dev-launcher inserts its own view controller above react-native-screens' stack, so the screens' status bar options never reach UIKit and the bar never hides there, rotated or on /game (see @tastic/core's CLAUDE.md, "Status bar: per-screen options"). Check it in a preview/production build or a local Release build.
- **It needs a new native build.** `UIViewControllerBasedStatusBarAppearance` only reaches Info.plist at prebuild, and the app.json plugin list changed too, so the fingerprint runtime version moves on: an OTA update from here on won't reach an older binary.
- Android gets the same options from react-native-screens (no Info.plist key there). Not checked on a device on either platform.

## Gesture worklets leaked the screen through runOnJS (2026-10-18)

`TouchInputLayer`'s Pan and Tap worklets called `runOnJS(handleTurn)` and `runOnJS(handleActivate)`. react-native-worklets holds a runOnJS target from native code (a Hermes GC root) for as long as the worklet's cached copy lives, and that copy lives as long as the component holds its Gesture, so the component's own callbacks pinned it in memory forever (found in Solitaire, where every dealt card leaked). Fixed with `@rific/core` 0.5.0's `useWorkletCallback` (a stable key per callback) and `callWorkletCallback` (module level): the worklets call `scheduleOnRN(callWorkletCallback, key, snakeId, direction)`. The keys are stable, so the ref-based gesture stability is unchanged. `OnboardingOverlay`'s `withTiming` completion is a one-shot the component does not keep, so it calls `scheduleOnRN(onComplete)` directly. Not verified on a device or with heap snapshots. JS only, so it can ship in an OTA. Both files import `scheduleOnRN` from `react-native-worklets` now (reanimated 4 deprecates `runOnJS` in its favor), so there is no `runOnJS` left in `src/`.

## Touchscreen browsers: no pinch-zoom on /game (2026-10-20)
